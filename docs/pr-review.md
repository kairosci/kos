# Pull request review

Review date: 2026-10-16.

PRs 113 and 114 only update pinned artifact action revisions in the ISO workflow. The revisions resolve to the official v8.0.2 download and v7.0.2 upload releases. Both use Node 24 on GitHub hosted ubuntu-latest runners; the existing named artifact inputs and download directory contract remain supported. Required checks passed. PR 113 was squash merged first; PR 114 was updated against the resulting base and squash merged after fresh checks. Merge bodies are empty and remote branches were deleted. The ISO publication workflow itself was not run as part of this review.

PR 117 is not ready for merge. `scripts/lib/userconf.sh:migrate_user_config_dir` moves entries into an existing destination without checking collisions first. A same-named file can be overwritten; a same-named directory can fail after earlier entries have already moved. Detect all collisions before mutation and preserve personal data with explicit backups or fail before moving anything. `hooks/theme-set.d/wallpaper` reuses an output based only on logo and palette timestamps, so a changed monitor geometry leaves the old image cached; include geometry in cache validity. That hook also duplicates a fallback and suppresses probe errors without the localized warning required by the repository. Green CI does not establish these cases are safe.

PR 64 is not ready for merge. It unpacks and repacks a package while retaining the original `.MTREE` after removing a packaged file. Its file list and integrity metadata no longer describe the archive. Repacking under the same filename also obscures artifact provenance. The changed legacy `scripts/lib/release.sh` is outside the current ISO publication path, so it does not establish a fix for today's workflow. It requires a current reproducer and a coherent package build with regenerated metadata.

The clock branch depends on PR 117's OS configuration migration. Its own validation can pass on this workstation while the parent migration still has an unsafe collision case. Keep the clock PR as a dependent draft until that prerequisite is corrected and reviewed. This review covers the listed changes and their critical paths; it is not a proof that every function in the entire repository is defect free.
