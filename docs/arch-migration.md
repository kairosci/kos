# Arch runtime migration

The application launcher sprint implements `os app browser`, `os app editor`, `os app files` and `os app settings` without sourcing or executing Omarchy. Browser selection follows the XDG browser preference with the HTTPS MIME association as a fallback when the browser setting is empty. The graphical editor and file manager follow the text and directory MIME associations. Settings opens the existing HyprMod desktop entry. This is a new command surface; existing `os launch`, terminal editor preferences, shortcuts and other native commands retain their current behavior.

`modules/os/data/app-launch.json` owns role selection and the private browser action identifier. `modules/os/scripts/lib/app-launch.sh` owns resolution and validation. User desktop entries take precedence over system entries, including hidden overrides. The launcher passes a desktop entry ID and the original argument vector to UWSM; it does not parse or evaluate the desktop entry Exec line. UWSM supports desktop entry IDs and action IDs through its [documented application launcher](https://github.com/Vladimir-csp/uwsm/blob/master/man/uwsm-app.1.scd).

`os app browser --private` requires a declared `new-private-window` desktop action with a corresponding command. A browser without that action fails before launch instead of opening a normal window. This checks the desktop entry contract; the selected browser owns the implementation of private browsing. App arguments beginning with a dash are rejected except for this private browser request. Paths beginning with a dash can be supplied as absolute paths. Shell metacharacters, spaces and URLs remain literal arguments. Graphical editor launch follows MIME preferences and does not replace the legacy terminal editor command.

`os app --resolve browser https://example.org` reports the selected entry and argument vector as JSON without launching anything. The same read-only resolution is available for every role. `make setup SCOPE=cli` installs the dispatcher, its library, role policy and all six message catalogs through the existing privileged pipeline. It does not synchronize packages, modify application defaults, reload Hyprland or restart desktop services. The launcher requires jq, XDG utilities and UWSM, and selected applications must already be installed.

This sprint establishes application dispatch independent of the Omarchy entrypoint. It does not establish parity for the complete applications capability: native menu integration, terminal working directory handling, all historical launch options and independent shortcuts remain to be evaluated. The migration assessment therefore keeps every capability unverified and refuses removal of the runtime or repository. The current kernel, login session, locker, audio, network and recovery entries remain the active implementations.

The next desktop sprint should introduce an isolated compositor and shell trial profile with explicit ownership of session startup, notifications, launcher, wallpaper and the single locker. It must be tested independently before replacing the active session. Kernel selection still requires the trial boot and hardware checks described in [the kernel assessment](kernel-review.md). Package source retirement requires alternatives for every package supplied only by the current repository and a tested update and recovery path.
