# Code architecture

Bash has no native classes. Each executable file and sourced module exposes a namespaced static entry method, derived from its repository path, which owns initialization and the existing operation. Existing exported helpers remain callable where setup, installed consumers and upstream interfaces require them. ClockWidget additionally uses a constructor and an associative array for instance state. This is a static module organization, not private scope or inheritance: Bash assignments remain global unless explicitly local, and source contracts and exit statuses remain observable.

Sourced provisioning stages return to their caller. Entry methods are invoked directly, never in a conditional that would disable errexit inside them. The internationalization and locale libraries preserve the caller's shell options. Initializers preserve source paths, argument forwarding, trap lifetimes and the public interfaces consumed by installed scripts. These constraints matter more than changing a function's spelling.

Lua files expose a named table with a run method that returns the same native module value as before. QML components already define reusable object types with properties and methods. The JavaScript media model uses a constructor and a singleton instance; its Node test files use native classes with static suite entry methods. jq retains its native functional filter model.

Configuration, translations, desktop entries, manifests, workflow files, unit templates, images and documentation remain declarative data in the formats their consumers require. Making those files executable would violate data and code separation and break native tools. Generated fixture text inside tests is input to a test, not a separately executed repository module.

The structural test scans tracked source files for the corresponding module entry point. Behavioral suites still establish the original APIs and failure semantics; a class-shaped wrapper alone does not prove encapsulation, correctness or migration parity.

Validation of this change on 2026-10-16 executes 2,038 root assertions across 43 suites, plus the OS dispatcher, cleanup, performance, privacy and opt-in debloat suites with 64, 71, 68, 90 and 15 assertions. The JavaScript media suites pass 60 tests. ShellCheck uses the repository CI file scope. The native Quickshell engine compiles the media components, and session setup validates and applies the clock in the top-right corner. A portable official PowerShell binary, checked against its published SHA-256, parses the downloader and exercises fixture assembly, checksum, cleanup and overwrite protection without publishing or downloading release artifacts.

The live verifier retains its two existing findings for missing EasyEffects and the inactive DNS failover monitor. Independent component verifiers retain their baseline findings: cleanup reports three, performance reports five and the retired Yazi gate reports one. Those same results occur against the pre-refactoring revision on this workstation. They are recorded rather than hidden or used as a reason to delete personal configuration. Structural and behavioral checks do not establish functional parity after removing Omarchy; that transition is still unimplemented.
