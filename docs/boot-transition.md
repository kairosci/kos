# EFI boot transition

The workstation currently boots Limine from firmware entry 0001. Its FAT ESP is mounted at `/boot` and its encrypted Btrfs root uses per-entry kernel arguments for root selection, hibernation resume and AppArmor. The boot inventory found two current kernel images, six snapshots with historical images and an EFI fallback. GRUB was not previously installed despite an older repository stage for provisioning it.

`make setup SCOPE=boot-assessment` records the actual mounts, firmware entries and boot file inventory under the root owned `/var/lib/os/boot-assessment`. The Lua parser validates referenced images as PE executables and checks the BLAKE2b digest used by Limine. It rejects missing images, paths outside the ESP, duplicate fields, unsupported protocols and integrity drift. It preserves separate snapshot root arguments. No firmware entry or boot preference is changed by assessment.

`make setup SCOPE=grub-trial` prepares a GRUB EFI candidate with `--no-nvram`, leaves the firmware BootOrder intact and preserves the existing Limine EFI image. Its generated menu chainloads the same verified EFI images with their original arguments, including encryption, resume and security settings. Menu policy lives in `data/component/boot/policy.json`; pure parsing and rendering live in Lua. The menu is checked with `grub-script-check` before publication. The root boot hook regenerates it from the current Limine inventory while that inventory remains authoritative. This is a transitional dependency, not completed independence from Omarchy.

GRUB supports passing arguments to chainloaded EFI images according to the [GNU manual](https://www.gnu.org/software/grub/manual/grub/html_node/chainloader.html). The hash format comes from [Limine configuration documentation](https://github.com/limine-bootloader/limine/blob/v12.x/CONFIG.md). Reusing verified EFI images avoids replacing their initramfs or reconstructing encryption arguments from static defaults.

Installation and syntax validation cannot establish firmware or hardware success. Before replacing the default bootloader, perform a real trial boot through the candidate, verify encrypted unlock, the persistent root, graphics, networking, audio, suspend, resume and recovery. Keep the current kernel and Limine fallback until those checks pass. No automatic reboot or deletion of recovery entries is part of these scopes. The request to migrate the project to Lua and Lua starts with this pure Lua component; Bash remains the tested privileged entrypoint during the transition.

The candidate is registered as a separate firmware entry with `efibootmgr --create-only`; the previous BootOrder is checked afterward and remains unchanged. A one-time trial can be selected from the firmware boot menu under OS GRUB trial. Limine and the EFI fallback remain available. GRUB is an alternative with an explicit OS-owned menu, not an established security improvement over Limine.

After the user chooses a trial at the next restart, `make setup SCOPE=boot-trial-select` validates the inventory and menu, identifies the unique firmware candidate by exact label and EFI path, sets only BootNext and checks both its value and unchanged BootOrder. It does not restart the machine. A failed trial remains distinct from the permanent firmware selection.
