# Protezione storica delle anteprime

Il sottoprogetto conserva l’integrazione storica con Yazi per mascherare anteprime di percorsi sensibili. Yazi è ritirato dal desktop corrente: questi sorgenti non vanno riattivati attraverso launcher, hook o helper gestiti. I dati personali restano conservati.

La precedente policy usava diciannove pattern di percorso e segnali di inattività per ripulire lo stato delle anteprime. È una protezione visiva, non cifratura, controllo degli accessi o difesa contro programmi che leggono i file direttamente. Non inserire password in variabili d’ambiente o argomenti di processo per riprodurre gli esempi storici.

Una futura sostituzione deve dichiarare il proprio confine di fiducia, verificare il comportamento effettivo e rispettare l’unico locker della sessione. La migrazione non deve trasformare un componente ritirato in una nuova dipendenza attiva.
