# Concise Communication

Use short, direct wording in progress updates and final reports. Include the result, material evidence, and any blocker. Remove repeated context, obvious implementation detail, generic introductions, and commentary that does not help the user decide or review.

Create pull requests with an empty body by default. Add body text only when the user requests it or an external repository requirement makes it necessary; use the shortest text that satisfies that requirement.

Brevity does not remove required technical evidence, safety information, limitations, attribution, or deliverables from another applicable skill. Follow those requirements without repeating them.
